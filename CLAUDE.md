# Beigale Insights — Landing Page

Credibility-only one-pager for a boutique M&A commercial advisory firm. Built to make a pre-vetting visitor (banker, lawyer, corp-dev) trust the firm in under a minute — not to capture leads or rank in search. As of the 2026-07-31 brief, the firm's positioning spans two services — pre-deal commercial due diligence and post-deal commercial value creation — not diligence alone; see Lessons Learned.

## Stack

- Static HTML/CSS. No build step, no framework, no bundler.
- Vanilla JS only if strictly needed (e.g. mobile nav toggle, smooth anchor scroll) — kept minimal.
- English only, LTR.

## DO NOT

- Do not add a lead-capture form. Contact is email + WhatsApp link only (see spec.md §4.7).
- Do not use teal (`--color-accent`) for large fills, backgrounds, or buttons-as-blocks — sparse accents only.
- Do not let any section read as a dense text block — short lines/paragraphs everywhere, per brief.
- Do not add decorative or filled icon sets — line icons only, one per pillar/credibility point, consistent stroke weight.
- Do not add multi-page routing, a CMS, or a blog/resources section — single static page only.
- Do not add analytics/tracking beyond basic pageview unless explicitly requested.
- Do not add motion/animation beyond subtle scroll-reveal — no decoration for its own sake.
- Do not introduce a second language or a language switcher.

## Lessons Learned

### כלל קריטי — Dark background is scoped to Hero + the dark "About" section only, nothing else
Client approval of the hero's dark treatment does not extend dark backgrounds to other sections. Confirmed explicitly: only Hero and the dark About section (renamed repeatedly — currently "About Beigale" per the 2026-07-31 brief, not yet built — see naming chain in the color-tokens table above) use dark backgrounds; the light sections (currently "What We Do," "Who We Work With," and Contact, pending the 2026-07-31 rebuild) all stay on the light `--color-base` background. Do not default to dark for a section just because it "feels" more premium — this needs explicit approval per section, same as the hero did.

### כלל קריטי — Accent color is chosen by background, not free choice: gold on dark, teal on light
Superseded 2026-07-17 (was: "gold anywhere on the page"). Client rule as of 2026-07-17: gold (`--hero-accent`) is used only for word-level emphasis on dark-background sections (Hero, the dark About section); teal (`--color-accent`) is used only for accents (icons, links, emphasis) on light-background sections. Never mix — don't put gold text on a light section or teal icons on a dark section. This also happens to fix a real contrast bug: gold on the light `--color-base` measures ~1.6:1 contrast, unreadable: gold only works against the dark hero/about backgrounds. Still sparse-only either way — never a large fill.

**Exception (2026-07-21):** client explicitly asked for gold on the Engagements card top-border, overriding this rule for that one spot, knowingly accepting the washed-out ~1.6:1 look on the light `--color-base` background — client was shown the pale render and chose to keep it anyway. Only the **Focused Commercial Risk Assessment** card uses gold; the **Full Commercial Due Diligence** card was explicitly reverted to teal (`--color-accent`) per client request right after. Do not silently "fix" the gold one back to teal, and do not extend gold to the Full card to "match" — this split is intentional, not an inconsistency. Don't extend gold-on-light to any other element without the same explicit sign-off. **Resolved (2026-07-31):** once "Engagements" is rebuilt as "What We Do" (see Lessons Learned below), this gold/teal split carries over to the two new service cards, same position as before — Tomer confirmed "exactly like Engagements": **Card 1, Commercial Due Diligence (first position) = gold**, **Card 2, Post-Deal Commercial Value Creation (second position) = teal**.

**Second exception (2026-07-31, same day; colors swapped 2026-08-01):** the same gold-on-light pattern was extended again, this time to "Who We Work With"'s two audience blocks — as of 2026-08-01, Acquirers block = gold (tint/border only, never text), Leadership Teams block = teal (was the reverse mapping until 2026-08-01). See Lessons Learned below. Three exceptions now exist for gold-on-light; all icon/border/background only, never text, to avoid the ~1.6:1 contrast problem.

### כלל קריטי — 2026-07-31, later same day: "What We Do" and About Beigale headlines made fully unbreakable per-sentence — required lowering their mobile font-size floor to avoid clipping
Tomer's ask evolved further: for the "What We Do" headline, each full sentence ("Commercial clarity before the deal." / "Commercial progress after it.") must render as one complete unbroken line — no internal wrapping at all, not even between "before" and "the deal." Implemented by nbsp-binding **every space within each sentence** (`Commercial&nbsp;clarity&nbsp;before&nbsp;the&nbsp;deal.<br>Commercial&nbsp;progress&nbsp;after&nbsp;it.`), same pattern already used on the About Beigale headline's "Senior&nbsp;commercial&nbsp;judgment." line.

**This exposed a real bug, not just a style choice:** both headers used `font-size: clamp(1.65rem, 6vw, 2.75rem)`, and on phones ≤440px wide the `6vw` term falls below the `1.65rem` floor, so the floor (26.4px) becomes the actual applied size — too large for a fully unbreakable ~28–36 character sentence to fit inside the ~270–340px content width at 320–390px viewports. With `&nbsp;` preventing any wrap, the overflow wasn't just "ugly," it got silently clipped off-screen by `body { overflow-x: hidden; }` — i.e. part of the headline was invisible on small phones. **Verified this really happened** via headless-browser `scrollWidth` checks (14px clipped at 320px width) before fixing it — don't assume nbsp-bound text "just wraps to fit."

**Fix:** both `.what-we-do__header` and `.why-us__header` now use a lower, more aggressive fluid clamp below 500px width — `clamp(1rem, 5.3vw, 2.75rem)` for What We Do, `clamp(1.1rem, 5.6vw, 2.75rem)` for About Beigale (slightly larger because its bound phrase is shorter) — with a `@media (min-width: 500px)` override restoring the original `clamp(1.65rem, 6vw, 2.75rem)` for tablet/desktop, where there's enough width that the floor never causes clipping. Verified zero horizontal overflow from 320px through 1440px after the fix. **If a headline is ever changed to use full-sentence nbsp-binding again, check for this same clipping risk at ≤440px width before shipping** — don't assume the existing clamp values are safe just because they looked fine on desktop.
